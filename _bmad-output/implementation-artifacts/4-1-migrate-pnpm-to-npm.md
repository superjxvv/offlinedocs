# Story 4.1: Migrate Monorepo from pnpm to npm

Status: done

## Story

As a developer,
I want the monorepo to use npm instead of pnpm,
So that I can install dependencies and run the project without needing pnpm installed.

1. **Given** a fresh clone of the repository, **When** I run `npm install`, **Then** all dependencies install without errors **And** the workspace contains three packages: @offlinedocs/shared, @offlinedocs/fetcher, @offlinedocs/server.

2. **Given** the monorepo is installed, **When** I run `npm run build`, **Then** all three packages build successfully with shared building first **And** each package produces output in its dist/ directory.

3. **Given** the monorepo is installed, **When** I run `npm test`, **Then** vitest runs across all packages with zero errors.

4. **Given** the root package.json, **When** I inspect it, **Then** it defines `"workspaces": ["packages/*"]` **And** does not reference pnpm in any scripts.

5. **Given** the repository, **When** I look for pnpm-specific files, **Then** `pnpm-workspace.yaml`, `pnpm-lock.yaml`, and `.pnpm-store/` do not exist **And** `.npmrc` contains only npm-compatible settings (or is removed).

6. **Given** the repository, **When** I inspect `package-lock.json`, **Then** it exists and was generated by npm.

7. **Given** the CI workflow (`.github/workflows/ci.yml`), **When** I inspect it, **Then** it uses npm commands (`npm ci`, `npm run build`, `npm test`) **And** does not reference pnpm or `pnpm/action-setup`.

8. **Given** the README.md, **When** I read it, **Then** all commands reference npm (not pnpm) **And** the Quick Start section uses `npm install` and `npm run build`.

9. **Given** the workspace dependency declarations in fetcher and server package.json, **When** I inspect them, **Then** `@offlinedocs/shared` uses a version like `"*"` or `"0.0.0"` (npm workspace-compatible) instead of `"workspace:^"`.

## Dev Notes

### Architecture Compliance

This is a **tooling migration** story — no application logic changes. The key constraint is that npm workspaces work slightly differently from pnpm workspaces:

**Critical differences:**
- pnpm uses `pnpm-workspace.yaml` for workspace config; npm uses `"workspaces"` field in root `package.json`
- pnpm uses `workspace:^` protocol for inter-workspace deps; npm uses `"*"` or explicit version
- pnpm's `--filter` flag becomes `npm -w <package>` or `--workspace` flag
- pnpm's `shamefully-hoist=false` in `.npmrc` is a pnpm-only setting — remove it
- pnpm's `allowBuilds` in `pnpm-workspace.yaml` has no npm equivalent (not needed)

### Build Script Migration

Current root build script:
```json
"build": "pnpm --filter @offlinedocs/shared build && pnpm --filter @offlinedocs/fetcher --filter @offlinedocs/server build"
```

npm equivalent (preserving build order — shared first, then fetcher+server):
```json
"build": "npm -w @offlinedocs/shared run build && npm -w @offlinedocs/fetcher run build && npm -w @offlinedocs/server run build"
```

Or alternatively using npm's built-in workspace awareness:
```json
"build": "npm -w @offlinedocs/shared run build && npm -w @offlinedocs/fetcher -w @offlinedocs/server run build"
```

1. **`npx` commands**: The README uses `npx offlinedocs-fetch` and `npx offlinedocs-server`. These should continue to work with npm since `npx` is part of the npm ecosystem. No changes needed for these.
2. **Node.js version**: Keep `.node-version` file as-is (it's not pnpm-specific).
3. **`vitest.workspace.ts`**: This file is vitest config, not pnpm-specific. Keep it unchanged.
4. **`tsconfig.base.json`**: Not pnpm-specific. Keep unchanged.
5. **The `dev:fetcher` and `dev:server` scripts** in root package.json use `pnpm --filter` — must be converted to `npm -w`.
